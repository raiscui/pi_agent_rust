### 关键问题

1. 当前 `read` 失败是否是 parser 或工具执行失败?
   - handoff 证据显示不是。`read` 工具能成功返回真实结果, 失败点在成功 tool result 之后, MiniCPM5 重复发起同名同参 `read`。
2. 修复是否应该只针对 `write`?
   - 不应该。用户明确要求证明通用 tool-use 能力。修复必须 provider-local, tool-agnostic, 只在重复同名同参且已有成功结果时拦截。
3. post-tool 回答约束是什么?
   - 工具返回后只总结真实 tool result。不要补造不存在的行号。不要把一行内容扩展成 JSON 列表。

### 做出的决定

- 决定: 优先在 agent 消费 provider 生成的 assistant message 到执行工具前加入 provider-local repeat guard。
- 理由: 这样可以阻止重复执行同一个成功工具调用, 并让最终回答来自真实 tool result, 不污染其它 provider。

### 遇到错误

- 暂无本 Session 新错误。历史 handoff 中的 blocker 是 `read` post-tool 重复调用到 `Maximum tool iterations (4) exceeded`。
